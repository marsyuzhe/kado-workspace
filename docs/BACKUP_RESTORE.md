# 备份、恢复与数据目录

设置 → 完整备份与恢复：创建包含SQLite与所引用附件的ZIP，可导出到用户选择位置。只复制一致性快照，不粗暴复制正在写入的数据库。业务数据库事务与受控附件写入共用可重入异步锁；压缩在后台isolate执行。备份最多250MB，展开最多500MB。

清单包含格式版本、Schema、生成时间、每类记录数量、文件长度与SHA-256。恢复先拒绝越界路径、链接、重名、结构错误、版本不兼容、缺失附件和哈希/数量不一致，再提供确认界面。校验用于发现损坏，不代表备份来源已经可信。

确认恢复后仍使用当前数据；退出并重新打开时，再次校验暂存内容，启用一个完整的新数据目录。之前的数据库与附件目录不被覆盖。恢复后剪贴板监听关闭，设备ID重新生成；API Key、SSH密码/私钥不在备份中，必要时在此设备重新配置。

数据基目录下：

- `links_toolbox.sqlite`、`attachments/`：初始数据。
- `backups/`：本机备份；独立介质保存由用户通过导出完成。
- `restore-staging/`：待验证/待激活恢复数据。
- `restored/<UUID>/`：已激活或保留的恢复代次。
- `active_data.json`：当前代次指针；未存在时使用初始数据。
- `active_data.previous.json`：恢复前的指针。
- `pending_restore.json`：已确认但尚未重启的恢复请求。

设置中的“恢复前数据回退”仅改变下次启动使用的指针；退出并重开后生效，各数据目录均保留。请勿在安排恢复/回退后继续编辑，以免新旧目录间产生需要手动迁移的内容。

便携模式基目录为EXE旁 `user-data/`。安装版基目录由系统path_provider决定；创建备份后的路径会在设置显示。也支持 `--data-dir=<绝对路径>` 或本进程 `LINKS_DATA_DIR` 环境变量，用于明确指定数据基目录。完整数据目录只能同时由一个进程使用。

## 启动失败时的保护

恢复失败会保留原数据，记录failed-restore请求并继续当前有效目录。若active_data.json本身被手动改坏，应用不会自动删除数据库。退出程序后，先复制完整数据基目录留存；可把active_data.json改名保留，再次启动回到初始数据。previous指针指向另一个完整恢复代次时，也可在保留原文件后使用该指针。

旧版0.1.0的诊断.sqlite快照不是含附件ZIP。`scripts/inspect_backup.py`可只读检查Schema1/2/3和SQLite完整性；不会执行恢复。直接从旧版本数据目录升级时，应用会运行v1/v2→v3增量迁移。不要删除旧库来升级。

备份不含系统安全存储，仍包含用户选定的普通笔记、聊天和附件内容；自行选择保存位置。签名私钥、工具缓存和环境配置也不会进入源码交付ZIP。
